# Production secrets and legal particulars

This guide prepares ClipKaro's **private VPS `.env`**. The source repository must never contain real provider secrets.

## Security model

- `.env`, `.env.production`, `.env.vps`, and `production-*.env` are Git-ignored.
- `scripts/configure-production-env.py` writes with mode `0600`, generates a fresh 64-byte URL-safe `SECRET_KEY`, and generates a fresh Razorpay webhook secret without printing either value.
- `PRODUCTION_CREDENTIALS_ROTATED=false` is the default. Paid launch remains blocked until provider credentials that were ever exposed in plaintext have been rotated in the provider dashboards, installed only on the VPS, and this flag is explicitly changed to `true`.
- `scripts/check-production-env.py` reports **only blocker names**, never secret values.
- `/api/v1/system/preflight` performs the final live provider/runtime checks. Offline configuration validation alone is not launch certification.

## 1. Create the VPS env

Preferred, interactive:

```bash
python3.12 scripts/configure-production-env.py --output .env
python3.12 scripts/check-production-env.py --env-file .env --require-ready
chmod 600 .env
```

If migrating an old local credential text file, you may use:

```bash
python3.12 scripts/configure-production-env.py \
  --credential-file /secure/local/path/api_key.txt \
  --output .env
```

The importer understands ClipKaro's current Groq and Razorpay fields. It intentionally ignores unrelated Gemini/Cerebras credentials because this release does not use them.

Do not keep the migration text file on the VPS after rotation.

## 2. Required production values

### Application / TLS

- `DOMAIN` — the real purchased public domain (for example `clipkaro.example`)
- `ACME_EMAIL` — real mailbox used by Caddy/ACME
- `SECRET_KEY` — generated by the configurator; never reuse development/demo values
- `APP_PUBLIC_URL=https://<your-domain>`
- `PRODUCTION_CREDENTIALS_ROTATED=true` only after actual provider rotation

### Transactional email

Resend is the preferred provider. Before paid launch configure:

- `RESEND_API_KEY`
- `EMAIL_FROM` using a sender/domain verified in Resend

SMTP remains an optional fallback. If Resend is not configured, provide `SMTP_HOST`, `SMTP_PORT`, a valid From mailbox, and matching SMTP authentication/TLS settings. The live preflight performs a secret-safe provider readiness check and never returns credentials.

### Groq

Configure at least one server-side Groq key. Up to five are supported for credential redundancy. Keys are mounted only into the media worker. Gemini/Cerebras keys are not used by the current ClipKaro runtime.

### Razorpay

Required:

- `RAZORPAY_KEY_ID` — must be a live key (`rzp_live_...`) for public paid traffic
- `RAZORPAY_KEY_SECRET`
- `RAZORPAY_WEBHOOK_SECRET` — generated locally, then configure the **same** secret in Razorpay Dashboard

Webhook target:

```text
https://<your-domain>/api/v1/billing/razorpay/webhook
```

At minimum enable the subscription lifecycle events already listed in `docs/RAZORPAY_BILLING.md`.

### Public legal / consumer particulars

These are intentionally public and must describe the actual operator. Do not invent them:

- `LEGAL_OPERATOR_NAME`
- `LEGAL_OPERATOR_ADDRESS`
- `LEGAL_CONTACT_EMAIL`
- `PRIVACY_CONTACT_EMAIL`
- `CUSTOMER_CARE_EMAIL`
- `CUSTOMER_CARE_PHONE`
- `GRIEVANCE_OFFICER_NAME`
- `GRIEVANCE_EMAIL`
- `GRIEVANCE_PHONE`
- `LEGAL_GSTIN` when applicable
- `LEGAL_PAN` when applicable

ClipKaro rejects obvious placeholders, malformed contact values, and malformed PAN/GSTIN values when supplied.

The Department of Consumer Affairs publishes the Consumer Protection (E-Commerce) Rules, 2020 and amendment materials. MeitY publishes the Digital Personal Data Protection Rules, 2025 and related enforcement material. Have the final public legal notice/policies reviewed for the operator's exact business structure and obligations; code validation only checks completeness/plausibility, not legal truth.

## 3. Rotate any exposed provider credential

If a key or secret was ever committed, pasted into chat/issues, emailed in plaintext, or included in a shareable ZIP/text file:

1. Create a new provider credential in the provider dashboard.
2. Put the new value only in the private VPS `.env` / secret manager.
3. Revoke the old credential.
4. Test the new credential.
5. Set `PRODUCTION_CREDENTIALS_ROTATED=true`.

The flag is an operational attestation. It does not replace actual rotation.

## 4. Validate before starting paid traffic

Offline shape check:

```bash
python3.12 scripts/check-production-env.py --env-file .env --require-ready
```

Compose configuration:

```bash
docker compose --env-file .env -f docker-compose.hostinger.yml config --quiet
```

Start the stack:

```bash
docker compose --env-file .env -f docker-compose.hostinger.yml up -d --build
```

Then authenticate as an admin/creator and call:

```text
GET /api/v1/system/preflight
```

Public paid traffic is allowed only when:

```json
{
  "paid_launch_ready": true
}
```

That requires all of the following at the same time:

- production configuration policy passed
- FFmpeg/storage passed
- ClamAV passed
- isolated worker heartbeat passed
- API-ASR provider configuration + worker heartbeat passed (or the explicitly selected local qualification runtime passed)
- transactional email readiness passed (Resend preferred; SMTP fallback supported)
- Razorpay live read-only authentication passed
- real legal/operator/customer-care/grievance fields passed

Groq semantic-ranking degradation remains a warning because deterministic ranking is the product fallback. API ASR provider readiness is a separate required processing signal and is reported by the media worker without exposing provider secrets to the public API container.

## 5. What must never be committed

Never commit or paste:

- `SECRET_KEY`
- SMTP passwords
- Groq API keys
- Razorpay Key Secret
- Razorpay webhook secret
- session/reset tokens
- raw `.env`

The public Razorpay Key ID may be shown to the browser by the billing API, but the Key Secret remains server-only.
